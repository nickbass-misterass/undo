transactional edits

All blocks or nothing.

An EDIT can carry multiple FIND/REPLACE blocks. Undo checks every block first. If a single one is missing, nothing is applied — the file never ends up half-edited. And edits are idempotent: applying the same block twice changes nothing the second time.

[ 01 ]

Atomic

All FIND blocks are validated before any write. One missing block → nothing changes. No partial states.

[ 02 ]

Idempotent

If a block is not found, Undo reports it and skips. It never duplicates lines — applying an EDIT twice is a no-op the second time.

[ 03 ]

Line-ending safe

CRLF vs LF is normalised on the fly. A Unix edit applies cleanly to a Windows file without touching the rest.

help about the program

What is Undo, really?

A small local agent that gives any AI assistant a working hand on your machine — through the clipboard, with full transparency and backups.

What it is

Undo is a terminal-style desktop application. You run it locally. The AI writes a command. You copy it into the clipboard. Undo reads the clipboard, executes the command on disk and writes the result back. You paste the result into the chat. That is the whole protocol.

No server. No account. No internet needed. No API keys. No telemetry. Everything happens on your machine.

Why it exists

Modern AI assistants are great at writing code and reasoning about it, but they cannot touch your file system. Cloud “tool use” requires accounts, keys, network and trust in a third party. Undo replaces all of that with the clipboard — the one channel every OS, every browser and every chat already supports.

How to use it — step by step

  1. Run Undo.py or Undo.exe.
  2. In your AI chat, ask: “Create a Python script that prints hello.”
  3. The AI answers with a block like the one shown above.
  4. Click Copy on that block.
  5. Undo executes within a second. It saves the file and puts the result into the clipboard.
  6. Paste the result into the chat.
  7. The AI confirms and continues.

What AI must always remember

  1. No direct file access — only through Undo.
  2. The user is the mediator: they copy and paste blocks.
  3. One command = one code block. Don’t mix commands.
  4. If an EDIT fails, read the file first, then send a new EDIT.
  5. Don’t invent paths — ask Undo: TREE: or LIST:.
  6. Always check the result — Undo returns it to the clipboard.
  7. For long commands Undo returns a compact summary: N lines.

Safety and privacy

  • No network access by design. Everything is local.
  • Every destructive operation creates a backup first.
  • Auto-cleanup keeps only the N most recent versions of each file.
  • The user is always the mediator. Nothing runs without a copy.
  • As with any shell tool — do not paste commands you don’t understand.

Compatible AI assistants

Anything that can show a text block with a Copy button: ChatGPT, Claude, DeepSeek, Gemini, local LLM frontends (Ollama, LM Studio, SillyTavern), even Notepad.

questions and answers

The system stays under your control.

Does Undo run commands by itself?

Yes. When a command with a marker lands in the clipboard, Undo recognizes it automatically and shows the result in the log.

What if a command doesn’t work?

Undo returns an error message. Before the next edit the AI can request the file contents or specific lines to prepare a precise fix.

Can I see what changed?

Yes. The DIFF command shows the difference against the latest backup. RESTORE brings back a chosen version and saves the current state first.

How do I hand over project context?

Run CTX and paste the assembled context into the chat. It includes project metadata, description, notes, tasks and log.

Is my data sent anywhere?

No. Undo has no network code by design. Nothing leaves your machine.

Do I need Python installed?

Only if you run the .py source. The compiled .exe works on its own.
